# BTT Pi TFT50 V2.1 на Radxa Dragon Q6A

Проверенное подключение использовало разъём DSI **J10, 39 pin**, переходник
Radxa 39→15 pin для Raspberry Pi 7-inch Display и TFT50 V2.1. Отключите
питание платы перед установкой шлейфа. В аппаратном протоколе отсутствуют
фото ориентации контактов и сведения об отдельном питании дисплея.
[Протокол исходной установки](../../reference/validation/btt-pi-tft50-v2.1-2026-10-15.json)

| Устройство | Что задаёт единый оверлей |
| --- | --- |
| Питание LCD | TLMM GPIO80 удерживается в единице. На Q6A V1.21 это линия LCD_VCC_EN, управляющая ключом U14 шины VCC_3V3_LCD. |
| Панель и мост | DSI → Toshiba TC358762 → панель Raspberry Pi 7-inch-совместимого типа. Ожидаемый режим 800×480. |
| Подсветка и питание панели | Контроллер ATtiny по I²C13, адрес `0x45`. |
| Тачскрин | FT5406 по I²C13, адрес `0x38`, координаты 800×480 и инверсия обеих осей. На этом подключении у узла тача отсутствует рабочая линия IRQ. |

Для этой версии ядра драйверу нужны два патча. Первый включает polling с
периодом 17 мс. Второй учитывает число точек в `TD_STATUS` и отпускает
исчезнувшие контакты. Этим определяется точность касаний.
[Исходники и авторство](../../../target/sbc/radxa_dragon_q6a/driver/README.md)

## Установка на плате

Целевая система — Radxa OS R2 на Q6A, Ubuntu 24.04.5 LTS, ядро
`7.0.11-7-qcom`. При обычной установке скрипт предложит через APT недостающие пакеты.
Для предварительной проверки с `--plan` их можно установить вручную:

```sh
uname -r
sudo apt install --no-install-recommends python3 build-essential patch \
    device-tree-compiler kmod initramfs-tools-core "linux-headers-$(uname -r)"
```

Перенесите весь каталог `target/sbc/radxa_dragon_q6a/` на плату удобным
способом. В каталоге комплекта запустите от обычного пользователя:

```sh
sh setup.sh --plan
sh setup.sh
```

Сборка выполняется на Q6A. Исходник драйвера, лицензия и патчи уже входят
в комплект. Проверяются хеши исходника, каждого применённого патча и DTBO,
а также соответствие модуля текущему ядру. Сборка кэшируется в
`${XDG_CACHE_HOME:-$HOME/.cache}/btt-pi-tft50/`. Установщик вызывает
`sudo` для чтения EFI и записи файлов. По умолчанию он использует запись,
на которую указывает `loader.conf`. При неоднозначном выборе укажите запись
вручную. Например, для штатной записи:

```sh
sh setup.sh --entry "/boot/efi/loader/entries/$(cat /etc/kernel/entry-token)-$(uname -r).conf"
```

| Текущее состояние | Результат |
| --- | --- |
| DSI свободен | Установщик добавит один `q6a-btt-pi-tft50-v21.dtbo`. |
| Установлены прежние BTT `display` / `power` или проверенный штатный RPi7 | Установщик покажет файлы, проверит их SHA-256 и запросит подтверждение. Enter отменяет замену. `sh setup.sh --replace` подтверждает её заранее. |
| Единый профиль и модуль уже установлены | Повторный запуск проверит комплект и загрузочную конфигурацию. |
| DSI занят неизвестным профилем или файл известного профиля изменён | Установщик остановится до изменения EFI. |

Перед записью установщик применяет весь итоговый список оверлеев к указанному
в EFI базовому DTB. Оверлей TFT50 занимает место первого заменяемого профиля.
Порядок остальных оверлеев, в том числе камер, сохраняется. Прежние DTBO
получают суффикс `.disabled`, чтобы `rsetup` не включил оба профиля.
Если на прежний файл ссылается другой пункт меню EFI, ссылка обновляется
на те же байты под сохранённым именем. Эту запись можно позже выбрать
через `--entry` и перенести отдельно. Установщик сверит SHA-256 её
`.dtbo.disabled` и сохранит файл для отката. Для исходной конфигурации создаётся
пункт `Q6A-before-tft50-v21-…`. Установщик проверяет хеши существующих
файлов перед записью. Путь к транзакции отката выводится в терминале.

Модуль устанавливается в `/lib/modules/7.0.11-7-qcom/updates/q6a-tft50/`;
уже выбранный модуль с известной контрольной суммой сохраняется. Подмена
модуля действует на все загрузочные записи данного ядра. Загрузка другой
записи EFI сама по себе меняет только конфигурацию DT. Для установки
заголовков и сборки после обновления ядра требуется отдельная проверка
совместимости. Автоматическая пересборка через DKMS не настроена.

## Доставка по SSH

Из каталога комплекта на Mac или Linux выполните:

```sh
sh deploy.sh radxa@radxa-dragon-q6a.local
```

Скрипт копирует комплект в новый каталог под `~/q6a-tft50/` и запускает
там ту же установку в интерактивном SSH-терминале. Последним аргументом можно
передать `--plan` или `--replace`. Для явного выбора записи EFI запустите
`sh setup.sh --entry …` на плате из напечатанного каталога.

## Проверка после перезагрузки

После применения выполните `sudo reboot` вручную. Проверьте следующие файлы
в новом сеансе:

```sh
cat /sys/class/drm/card*-DSI-1/status
cat /sys/class/drm/card*-DSI-1/enabled
cat /sys/class/drm/card*-DSI-1/modes
modinfo -n edt_ft5x06
cat /sys/bus/i2c/devices/*-0038/input/input*/name
cat /sys/bus/i2c/devices/*-0038/input/input*/poll
sudo evtest
```

Ожидаются `connected`, `enabled`, режим `800x480` и период `17`.
В `evtest` выберите тачскрин и проверьте нажатие, движение и отпускание,
затем попадание в элементы рабочего стола у каждого угла. Для `evtest`
может понадобиться одноимённый пакет. Если экран тёмный, проверьте
`journalctl -b -k` на ошибки ATtiny `REG_ID` у адреса `0x45`. Если
координаты неверны, проверьте выбранный путь `edt_ft5x06` и значение polling.

В прежней конфигурации после перезагрузки проверялись питание, изображение
и автозагрузка polling-модуля. Финальную правку обработки пакетов проверили
на загруженной системе. За 45 секунд записаны 467 событий, включая нажатие
и отпускание. Новый единый профиль пока проверен на DTB ядра. Проверка на
плате после перезагрузки, мультитач и suspend/resume остаются открытыми.
[Сравнение итоговых деревьев](../../reference/validation/unified-overlay.md)

## Откат

Если TFT50 установлен в нескольких записях EFI, откатывайте установки
в обратном порядке. Пока другая запись использует удаляемый DTBO или
модуль этого ядра, установщик остановит откат до записи и покажет её имя.

В каталоге текущего комплекта выполните команду с путём к резервной
копии, напечатанным при установке. Она также подходит для старых копий с
`transaction.json`. Защиту общих файлов выполняет версия `install.py`,
которую вы запускаете.

```sh
backup=/var/backups/q6a-tft50-ИМЯ_ИЗ_ВЫВОДА
sudo python3 install.py --rollback "$backup" && sudo reboot
```

Транзакция сохраняет прежние файлы и запускает `depmod`. Если после
установки меняли EFI-запись, например добавляли камеру, откат остановится
и укажет файл для сверки с `transaction.json`. Для восстановления при
тёмном экране используйте SSH или HDMI. Порядок отката исторической версии
со старыми `rollback.sh` приведён в исходном руководстве платы.
[Исходный PR платы](https://github.com/pOmelchenko/radxa_dragon_q6a/pull/1)
